Автономная HTML-утилита для устранения пропусков позиционных обозначений в XML-экспорте схем DipTrace (`.dchxml`).

## Запуск

Скачайте `index.html` (версия 1.0.0) и откройте его в современном браузере. Установка, сервер и подключение к интернету не нужны. Файл схемы обрабатывается локально, сетевых запросов в коде нет.

## Порядок работы

1. Сохраните резервную копию схемы и экспортируйте её из DipTrace в DCHXML.
2. Выберите или перетащите файл в окно утилиты.
3. Отметьте группы обозначений и задайте начальный номер (по умолчанию 1). NetPort по умолчанию исключён.
4. Проверьте таблицу замен, например `C1, C2, C4, C7 → C1, C2, C3, C4`.
5. Проверьте таблицу упоминаний в текстовых надписях и при необходимости снимите или поставьте отметки у отдельных замен. Флажок «Обновлять обозначения в текстовых надписях» отключает эту функцию целиком.
6. Проверьте список обозначений без номера (например, `XTAL`): они не перенумеровываются.
7. Скачайте исправленный DCHXML и протокол CSV с разделителем `;` и BOM UTF-8.
8. Откройте результат в DipTrace и проверьте схему, внешние ссылки и согласование с PCB.

Исходный файл на диске не перезаписывается. Результат получает суффикс `_RefDes_fixed.dchxml`, протокол — `_RefDes_changes.csv`.

## Алгоритм и комментарии

- Проверяются корректность XML и корневой элемент `Source Type="DipTrace-Schematic"`.
- Обрабатываются значения RefDes в Part внутри `Schematic/Components`; библиотека компонентов не перенумеровывается.
- Распознаются обозначения из буквенного префикса (латиница, кириллица, подчёркивание) и числа.
- Номера каждой выбранной группы уплотняются по возрастанию исходных номеров, а не по координатам на схеме.
- Одинаковые префикс и номер трактуются как секции одного компонента и заменяются совместно.
- Замены выполняются по смещениям с конца текста: каскадного переименования по совпадению строк нет.
- XML не сериализуется заново; текст вне замен сохраняется. Поддерживаются UTF-8 и UTF-16 с BOM; выходная кодировка сохраняется для распознанного входа.
- После замены проверяются XML, число секций, состав секций каждого обозначения (по Part Id) и число строк текста.

## Текстовые надписи

- Просматриваются все `<TextLine>` внутри `<Schematic>`, кроме блока компонентов: текстовые надписи (`Shape Type="Text"`), поля основной надписи (`Field`) и ячейки таблиц (`Cell`).
- Упоминание распознаётся как отдельное слово из префикса существующей группы и номера: `C11=12n`, `C5-C8`, `R16, R17`. Буквы, цифры и `_` рядом с ним исключают совпадение (`P3_PG_5V`, `I2C`, `300R`).
- Заменяются только упоминания переименованных обозначений; диапазоны остаются корректными, так как уплотнение сохраняет порядок номеров.
- Сомнительные случаи — часть составного слова (`NE8FAH-C5`, `x.C5`) или число (`R1.5`) — показываются, но по умолчанию не заменяются.
- Упоминания несуществующих обозначений (например, `C200` при 91 конденсаторе) помечаются «нет в схеме».
- Значения, имена и дополнительные поля компонентов не меняются.

## Обозначения без номера

RefDes, не подходящие под шаблон «префикс + число», показываются отдельной таблицей с типом (без номера, иерархическое, только номер, иной формат), числом секций, именем компонента и Part Id и попадают в протокол.

## Интерфейс и протокол

- Светлая тема по умолчанию, переключатель тёмной темы; выбор сохраняется в браузере.
- Протокол CSV (`;`, UTF-8 с BOM, экранирование полей) содержит строки «RefDes», «Надпись» (со статусом) и «Без номера».

В исходном коде добавлены комментарии к декодированию, разбору XML, перенумерации и скачиванию. Логика загруженной версии сохранена.

## Ограничения

Иерархические обозначения вида `#1.1-R1` не перенумеровываются, но показываются в таблице нераспознанных. Нет анализа иерархии и идентификаторов реальных компонентов: случайно одинаковые RefDes могут быть приняты за секции одного компонента. Проверка числа уникальных обозначений не заменяет полную проверку коллизий по идентификаторам. Парсер ожидает структуру DCHXML с тегами Schematic, Components, Part и RefDes; произвольные варианты XML и другие кодировки не гарантируются.

Внешние ссылки и PCB автоматически не обновляются. Для рабочего проекта обязательна проверка результата в DipTrace. Историческая сборка, обозначенная ранее как 1.1, проверена на реальном DCHXML DipTrace 5.3.5.1 (471 размещение, 202 строки текста) и на его копии с искусственными пропусками в одно- и многосекционных компонентах.
